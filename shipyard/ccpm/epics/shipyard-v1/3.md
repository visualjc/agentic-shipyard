# Task: Deliver workspace, ledger checkpointing, and context envelopes

## Description

Give a bound delivery its complete safe workspace and durable development-only
state without polluting product history: atomically create/resume the delivery
ID, feature branch, linked worktree, and parallel ledger entry; then checkpoint
records transactionally and dispatch role-specific context envelopes pinned to
exact product and ledger SHAs.

## Acceptance Criteria

- [x] A delivery atomically receives/resumes a stable ID, feature branch, linked
  product worktree, and ledger entry on an orphan `shipyard-ledger` branch
  outside product ancestry.
- [x] Delivery creation rejects product work directly on authoritative `main`
  and detects partial, ambiguous, or conflicting pre-existing workspace state.
- [x] The resolver handles linked worktrees, explicit delivery IDs, genuine
  ambiguity, concurrent checkpoints, and stale expected ledger SHAs.
- [x] Implementer, reviewer, and status envelopes contain only their allowed
  record paths and the minimum host-neutral adapter fields.
- [x] Workers reject a stale product SHA before loading any ledger record.
- [x] The ledger survives product branch deletion and is never included in a
  staged destination refspec or payload.
- [x] Disposable Git tests cover creation, interrupted resume, worktree
  recreation, ambiguity, and final cleanup handoff.
- [x] Evidence covers PRD AC-008, AC-009, and AC-010.

## Technical Details

- Reuse the proven common-dir resolver and optimistic ledger transaction model.
- Keep durable records and rebuildable/machine-local state in separate schemas.
- Make the final ledger seal verifiable without requiring a commit to contain
  its own SHA.
- Contribute workspace, branch, product SHA, and ledger SHA fields to the shared
  task-001 status projection.
