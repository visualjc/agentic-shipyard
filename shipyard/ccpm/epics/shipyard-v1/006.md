# Task: Deliver staged-pair promotion and finalization

## Description

Deliver the primary mixed-adoption workflow end to end: promote one reviewed
development SHA as sanitized cargo to a normal destination-owned PR, append
later reviewed revisions, verify human merge, and finalize without merging the
development PR.

## Acceptance Criteria

- [ ] Promotion requires current destination `main`, complete fresh evidence,
  verified binding/actor, and one-owner path classification.
- [ ] Git-native payload construction preserves all file modes/operations and
  rejects prohibited or unclassified metadata.
- [ ] The initial destination branch/PR is destination-owned and non-cross-
  repository; no development repository is exposed or retained as a writable
  destination remote.
- [ ] Destination feedback is implemented/reviewed on development, then
  appended as one sanitized descendant commit without force push.
- [ ] The manifest maps reviewed development SHAs to destination commits and
  verifies tree equivalence.
- [ ] Finalization verifies the expected destination merge, seals/pushes the
  ledger and reviewed tag, synchronizes exact mains, closes the development PR
  without merge, closes the issue, and deletes delivery branches.
- [ ] Path ownership and prohibited-metadata policy are revalidated before
  initial promotion, every revision, and finalization.
- [ ] Evidence covers PRD AC-011, AC-012, AC-013, AC-016, and AC-017.

## Technical Details

- Build on the proven local and private-fixture history model.
- Checkpoint every external step and revalidate refs before resume.
- Keep destination merge an observed human/team action, not a Shipyard command.
- Use three reviewable milestones: initial sanitized promotion, append-only
  reviewed revision, and post-merge resumable finalization.
- Acquire the shared mutation lock and contribute topology phase, manifests,
  destination refs/PR, blockers, and next action to status.
