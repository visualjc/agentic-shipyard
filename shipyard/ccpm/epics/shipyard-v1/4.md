# Task: Deliver scoped GitHub tracking authority

## Description

Implement the first provider mutation slice: select and verify a profile actor,
isolate Git transport credentials, enforce repository/operation allowlists, and
create development issues/PRs only in the bound development repository.

## Acceptance Criteria

- [ ] GitHub API mutations obtain the configured command-scoped actor and reject
  an unexpected login before the first write.
- [ ] The global active GitHub CLI account is unchanged before and after every
  operation.
- [ ] Authenticated Git disables inherited credential helpers and uses an
  ephemeral token environment without persisting or logging secrets.
- [ ] Issue and development-PR writes are allowed only in the configured
  development repository; destination workflow issues are prohibited.
- [ ] GitHub REST mutations are resumable and idempotently discover existing
  Shipyard-created records.
- [ ] Provider mutations return stable issue/PR IDs, URLs, expected head SHAs,
  and resume checkpoints for later ledger/status integration without requiring
  task 003 to own ledger storage.
- [ ] Evidence covers PRD AC-003, AC-004, AC-007, and provider portions of
  AC-019.

## Technical Details

- Separate API credentials from Git transport credentials.
- Use stable Shipyard markers and exact provider IDs for resume detection.
- Return actionable auth/permission errors without echoing tokens.
- Contribute provider identity, permission, record, and blocker fields to the
  shared status projection.

## Dependencies

- Depends on task 001 profile/binding and policy schemas.

## Effort Estimate

- Size: L
- Hours: 28–36

## Definition of Done

- [ ] Code implemented behind a GitHub adapter interface.
- [ ] Unit, negative-auth, redaction, and private-fixture tests pass.
- [ ] Credential/tracker documentation and recovery states are complete.
- [ ] Acceptance evidence names the exact product SHA and verifier.
- [ ] Independent code review has no unresolved accepted finding.
