# Task: Deliver scoped GitHub tracking authority

## Description

Implement the first provider mutation slice: select and verify a profile actor,
isolate Git transport credentials, enforce repository/operation allowlists, and
create development issues/PRs only in the bound development repository.

## Acceptance Criteria

- [x] GitHub API mutations obtain the configured command-scoped actor and reject
  an unexpected login before the first write.
- [x] The global active GitHub CLI account is unchanged before and after every
  operation.
- [x] Authenticated Git disables inherited credential helpers and uses an
  ephemeral token environment without persisting or logging secrets.
- [x] Issue and development-PR writes are allowed only in the configured
  development repository; destination workflow issues are prohibited.
- [x] GitHub REST mutations are resumable and idempotently discover existing
  Shipyard-created records.
- [x] Provider mutations return stable issue/PR IDs, URLs, expected head SHAs,
  and resume checkpoints for later ledger/status integration without requiring
  task 003 to own ledger storage.
- [x] Evidence covers PRD AC-003, AC-004, AC-007, and provider portions of
  AC-019.

## Technical Details

- Separate API credentials from Git transport credentials.
- Use stable Shipyard markers and exact provider IDs for resume detection.
- Return actionable auth/permission errors without echoing tokens.
- Contribute provider identity, permission, record, and blocker fields to the
  shared status projection.
