# Task: Harden recovery and prove release readiness

## Description

Turn the functional slices into a releasable v1: exercise every interruption
boundary, prove secret/metadata containment, complete both topology runbooks,
and close all PRD acceptance and Definition of Done items against one exact
release-candidate SHA.

## Acceptance Criteria

- [ ] Every external mutation checkpoint has an idempotent resume or explicit
  manual-recovery state after exact ref/provider revalidation.
- [ ] Concurrent mutation locks and stale process/host recovery behave safely.
- [ ] Tokens are absent from remotes, argv, logs, errors, ledgers, and
  destination content.
- [ ] Local suites cover both topologies, path/file-mode edge cases, dirty and
  divergent state, source refs, stale evidence, and cleanup retry.
- [ ] Opt-in private synthetic GitHub tests cover scoped identity, issue
  targeting, normal destination PRs, single-repository certification,
  exact-head merge verification, and metadata containment.
- [ ] All PRD AC-001 through AC-023 and DOD-001 through DOD-012 are closed with
  evidence against the exact release-candidate SHA.
- [ ] Independent release review has no unresolved accepted finding and all
  deferred behavior is accurately labeled.

## Technical Details

- Favor fault injection and resumable state assertions over happy-path reruns.
- Retain a reproducible synthetic fixture harness without depending on any
  production organization.
- Produce a release evidence index linking criteria, tests, SHAs, and reviews.
