# Task: Integrate planning lanes and public orchestration

## Description

Connect the proven mechanics into the opinionated Shipyard experience: classify
work, verify pinned dependencies, route to Matt-skill/CCPM planning lanes, and
guide a user through the eight progressive public commands without granting raw
dependencies lifecycle authority.

## Acceptance Criteria

- [ ] The orchestrator records large, small, bug, and review-only lane
  classification and selects the PRD-approved planning sequence.
- [ ] Setup/status validate the exact tested Matt-skills, maintained CCPM,
  Codex, runtimes, discovery paths, duplicates, and content receipts.
- [ ] Missing/modified/incompatible dependencies block; newer untested versions
  report `unverified`; no dependency is auto-upgraded or casually vendored.
- [ ] CCPM issue/merge/metadata operations remain behind Shipyard actor,
  topology, evidence, and path guards.
- [ ] CCPM planning/execution uses only the supported Codex path in v1; Claude
  Code and Cursor/Pstack remain documentation-only deferred integrations.
- [ ] Provider IDs/resume checkpoints and every slice-specific status field are
  bound into ledger state and the complete FR-018 public status projection.
- [ ] All eight public Agent Skills load focused references and return the next
  safe command without loading the complete operating model.
- [ ] Deferred Claude/Cursor/multi-account behavior is labeled unsupported and
  never implied by examples.
- [ ] Evidence covers PRD AC-020 and AC-023.

## Technical Details

- Keep dependency capabilities separate from source/version receipts.
- Reuse core commands rather than duplicating policy in Markdown skills.
- Include migration guidance without activating predecessor aliases.
- Verify every mutation command uses the task-001 repository lock and returns a
  deterministic blocker/next-safe-action status.
