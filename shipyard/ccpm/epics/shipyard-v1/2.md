# Task: Establish core package, binding, setup, status, and help

## Description

Create the minimal runnable Shipyard package and one complete read-only vertical
slice: bind an eligible repository to a profile, resolve the binding from its
main clone or linked worktree, and report status/help without guessing or
mutating provider state.

## Acceptance Criteria

- [x] A TypeScript ESM package exposes the `shipyard` CLI and project/user Agent
  Skill layout for Codex.
- [x] Versioned schemas validate profiles, staged-pair and single-repository
  bindings, path policies, operations, and lifecycle state.
- [x] A shared one-owner path classifier rejects unclassified and conflicting
  ownership and is reusable by sync, promotion, certification, and finalization.
- [x] A short repository mutation-lock primitive rejects concurrent mutations
  and validates process/host ownership before stale recovery.
- [x] The status projection model can aggregate delivery phase, product/ledger/
  destination SHAs, evidence freshness, provider refs, locks, graph freshness,
  blockers, and next-safe-action fields contributed by later slices.
- [x] `shipyard-setup` validates a complete topology, refuses implicit remote
  rewriting/provisioning, and requires explicit `--rebind` to replace state.
- [x] Bindings are keyed by Git common directory and resolve identically from
  the main clone and linked worktrees.
- [x] Missing, partial, duplicate, stale, or remote-mismatched bindings fail
  before mutation with setup/rebind guidance.
- [x] `shipyard-status` and `shipyard-help` are read-only and identify the next
  safe action.
- [x] Evidence covers PRD AC-001, AC-002, AC-021, and the foundational portion
  of AC-023.

## Technical Details

- Prefer pure validation/state modules and inject filesystem/Git adapters.
- Define a portable Shipyard home/config abstraction rather than embedding
  private policy in the package.
- Keep setup idempotent and never silently repair an unexpected repository.
- Define extension points so later tasks add status fields without duplicating
  binding or lock policy.
