# Exact-SHA delivery gate

Run after all ticket work integrates and after every accepted delivery-PR revision.

1. Verify the agentic repository, worktree, unique work branch, base SHA, exact candidate SHA, and clean/known dirty state.
2. Run the repository's targeted and full verification commands. Record exact commands, outcomes, environment limitations, and the candidate SHA.
3. Audit every acceptance criterion against observable evidence.
4. Invoke fresh independent `code-review` against the exact base/candidate range. Record standards and specification verdicts separately.
5. Resolve the bound ledger and read its canonical `.slipway/agent-overlay/` tree before cargo inspection. Refuse to seal this gate if the binding, canonical overlay, manifest, or required hydration health is unavailable, unreadable, or unhealthy. Inspect every commit patch and resulting tree in `review-base..candidate-SHA`, plus the final diff and tracked state; the final diff check is necessary but insufficient. Define the candidate changed public-instruction set across that full history as every tracked `AGENTS.md`, `CLAUDE.md`, and configured tracked public-instruction path changed by any commit in the range, including content later deleted. From the manifest and every canonical overlay file, derive and retain an inventory of its materialized private paths, tool/skill identifiers, and normalized headings, paragraphs, and list items. For each changed candidate paragraph or identifier at any point in the range, require a public authorization source: the pre-existing public contract at `<review-base>` or a canonical acceptance artifact indexed in the run's `artifacts.md`. Allow the confirmed generic local extension, host adapters, and team-facing guidance only when that source authorizes it. Reject materialized worktree-root `/AGENTS.local.md`, `/CLAUDE.local.md`, `/docs/agents/**`, and `/.slipway-local/**`; private supporting paths; overlay-only identifiers; and paragraphs derived only from the canonical overlay, from cargo, the candidate range, and the agentic PR diff, even if a later commit removes them. Record each compared source and its allow/reject disposition in the immutable `review` event's Verification performed section; fail closed when a source or disposition is ambiguous. Do not confuse reviewed Slipway template assets under an included product path with materialized overlay files.
6. Require agentic metadata and product changes to use separate commits. If any cargo commit is mixed or any materialized private overlay file is tracked, fix the boundary or remove the leakage on the agentic branch, then rerun this entire gate at the new head.
7. Seal the gate only when QA, acceptance, review, and cargo inspection all name the same exact candidate SHA and no blocking finding remains.

Any new commit, amended commit, rebase, merge, or branch-head change invalidates the gate. Plain records do not prove the SHA still exists or remains current; verify it before promotion.
